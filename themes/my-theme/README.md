# My Korea Media — 7.0

Белая Hugo-тема с навигацией по рубрикам, прямоугольными фотографиями, заголовками под превью, автором и датой. Интерфейс на русском, английском и корейском языках.

## Установка обновления

1. Сохраните копию действующей папки `themes/my-theme`.
2. Замените её **целиком** папкой `my-theme` из архива. Не смешивайте шаблоны разных версий.
3. Сохраните свой `hugo.toml`, публикации, изображения и настройки языков. Перезаписывать конфиг примером из архива не нужно.
4. Проверьте `hugo version`: требуется 0.158.0 или новее.
5. Запустите `hugo server`, затем `hugo --gc --minify` для публикации. Если CDN кэширует HTML, обновите этот кэш.

Файлы из корневых `layouts/` и `assets/` вашего проекта имеют приоритет над файлами темы. Если старая вёрстка осталась, проверьте локальные переопределения. Существующие URL разделов сохранены: `/posts/`, `/categories/`, `/tags/`, `/search/` с языковыми префиксами Hugo.

## Каталог самущилей

Скопируйте содержимое соседней папки `site-root/` из архива в корень Hugo-проекта. Подробная инструкция — `INSTALL.md` в корне архива и `OFFICES.md` внутри темы. Самущили редактируются вручную в YAML, отдельный файл на каждый офис. Сторонние сервисы для каталога не нужны.

## Главная и шапка

- Сверху — статичная, не закреплённая шапка: «Назад» и «На главную».
- На главной — крупные круглые изображения рубрик с тонкой рамкой и названием снизу.
- На остальных страницах — компактная горизонтальная навигация по тем же рубрикам.
- При наведении двигается только визуальное представление круга через CSS transform; размеры и положение соседних элементов не меняются. Учитывается `prefers-reduced-motion`.
- Убраны прежний крупный текст о сайте и серый фон.
- Нижняя панель с логотипом в центре и выбором языка сохранена.
- «Назад» вызывает `history.back()` как кнопка браузера, включая переход на другой сайт. При истории из одной записи кнопка неактивна; без JavaScript скрыта. «На главную» — отдельная ссылка.
- При установленной странице `/work/` в шапке и на главной появляется вход в каталог самущилей.

## Своя фотография и описание рубрики

Для существующей рубрики создайте файл, например `content/categories/путешествия/_index.ru.md`:

```yaml
---
title: "Путешествия"
description: "Маршруты, прогулки и поездки по Южной Корее."
image: "/images/categories/travel.webp"
translationKey: "category-travel"
---
```

Сам файл изображения в таком случае расположен в `static/images/categories/travel.webp`. Можно использовать и ресурс категории: положите `cover.webp` рядом с `_index.ru.md` и задайте `image: "cover.webp"`. Ресурсы bundle и `assets/` автоматически получают небольшие WebP-варианты. Квадратное исходное изображение размером 256–512 px удобно для круглой навигации.

Картинка рубрики используется **только в навигации**, отдельная большая обложка в её архиве не выводится. Название и `description` выводятся над публикациями; дополнительный Markdown после front matter также поддерживается.

При отсутствии отдельной фотографии тема использует миниатюру последней публикации рубрики. Если изображений нет совсем — первую букву названия в круге. Загружать случайные фотографии с внешних сервисов тема не будет.

Для EN и KO создайте соответствующие файлы `_index.en.md` / `_index.ko.md` с переведёнными названием и описанием. Если названия/адреса категорий различаются, используйте один `translationKey` для пары или тройки соответствующих рубрик. Названия таксономий в front matter публикаций должны соответствовать их языку. Тема переводит интерфейс, а не тексты ваших статей автоматически.

Системная рубрика `Pin` скрыта из обычной навигации. Настраиваются `params.pinCategory` и `params.hiddenCategories`.

## Карточки и фотографии статьи

На телефоне карточки идут в одну колонку, на планшете — в две, на широком экране — в три. Изображение 16:9, ниже заголовок (до трёх строк), дата и автор. Фотографии не имеют скруглений. Исключение — круглые изображения рубрик, выбранные для навигации.

Миниатюра выбирается из `image`, `thumbnail`, обложки bundle, первого изображения bundle или первой обычной Markdown/HTML-картинки. JPEG/PNG/WebP/TIFF/BMP из bundle/`assets/` получают WebP 480×270 и 800×450. SVG/GIF/AVIF выводятся без принудительной конвертации. Внешние изображения и картинки из `static/` не перекодируются; для них желательно заранее готовить подходящий размер.

В статье удалены прежние большие отступы и разделительная линия перед текстом. Авторская последовательность текста и изображений сохранена: тема не переносит фотографии из середины публикации и не дублирует `image` из front matter. Первая фотография в HTML статьи получает `loading="eager"` и `fetchpriority="high"`; последующие Markdown-изображения загружаются лениво.

Лид из `description` по умолчанию не дублируется над текстом. Его можно включить через `showArticleLead = true`. Сворачиваемое содержание включается `showArticleToc = true`; при наличии shortcode `toc` второй блок не добавляется.

## Раздел «Лента» вместо Posts

Для `/posts/` автоматически выводится локализованный заголовок: «Лента», «Feed», «새 글». Он используется и в `<title>` / Open Graph. Существующий автоматический `Posts` его не заменяет.

Описание можно задать в `content/posts/_index.ru.md`:

```yaml
---
title: "Лента"
description: "Новые записи, новости и заметки о жизни в Корее."
---
```

Создайте `_index.en.md` и `_index.ko.md` с переводами описания. Можно использовать Markdown после front matter — он будет описанием раздела. Альтернатива: `feedTitle` / `feedDescription` в языковых `[languages.ru.params]`, `[languages.en.params]`, `[languages.ko.params]`. Общий русский текст в корневом `[params]` будет общим для всех языков, поэтому для переводов используйте именно языковые секции.

## Шесть случайных похожих статей

Подбираются **до шести** уникальных материалов текущего языка, имеющих хотя бы одну общую обычную рубрику. Текущая статья, служебная рубрика Pin, страница поиска и публикации с `exclude_from_home: true` исключаются. При менее чем шести подходящих материалах показываются имеющиеся; чужие рубрики не подмешиваются.

При открытии страницы Hugo уже отдаёт подборку в HTML. Когда читатель приближается к ней, браузер загружает небольшой общий JSON-список её рубрики и выбирает шесть случайных статей заново. Список переиспользуется между статьями и имеет хэш в имени для обновления кэша. Скрипт не обращается ко всему архиву сайта и не требует сервера/API. При отключённом JavaScript или ошибке сети остаётся исходная подборка, случайная на момент сборки.

## Подгрузка следующей статьи

После статьи, блоков обсуждения и рекомендаций размещён переход к следующей публикации. При прокрутке к нему автоматически загружается следующий **более старый** материал того же раздела и языка. Затем можно продолжать чтение дальше по датам.

- Используются `IntersectionObserver`, `fetch`, `AbortController` и ES module.
- Загрузка начинается после прокрутки, а не сразу при открытии страницы.
- Одновременно загружается только один экземпляр каждого перехода.
- Заголовок добавленной статьи имеет уровень H2; шапка, нижнее меню и футер не дублируются.
- Внутренние ID и ссылки содержания получают уникальные префиксы.
- URL, canonical, заголовок вкладки и положение фокуса исходной страницы сохраняются. У каждого добавленного материала есть ссылка «Открыть отдельно» на его собственный URL.
- При ошибке доступна кнопка повтора и обычная ссылка. Автоматических бесконечных повторов нет.
- Без JavaScript остаются обычные переходы.
- Авторские `<script>` из подгруженной статьи не исполняются повторно. Встроенные iframe из shortcode VK/YouTube сохраняются. Если материал требует стороннего скрипта, откройте его отдельной страницей.

Для отключения автоматической загрузки задайте `autoLoadNext = false`. Кнопка ручной подгрузки и обычная ссылка останутся. Проверять загрузку нужно через `hugo server` либо веб-сервер, а не через `file://`.

## Telegram и VK под статьёй

В front matter материала:

```yaml
vk_discussion: "https://vk.com/..."
telegram_discussion: "https://t.me/ansanlife/123"
```

Показывается только блок, для которого задана ссылка. Если заданы обе — выводятся оба. Можно указать ссылку на конкретное обсуждение или на группу целиком. Поле `telegram` поддерживается как альтернативное имя для `telegram_discussion`. Ссылки должны быть полными (`https://...`).

## Ansan Life и канал уведомлений

В общем футере всех страниц размещено приглашение от администратора: о десятом годе жизни в Ансане, любви к городу и группе для общения, любимых мест, событий и полезных находок. Текст подготовлен на RU/EN/KO.

- `@ansanlife` — общение, вопросы, обмен находками.
- `@ansan` — уведомления, объявления и публикации от администрации.

Оба адреса находятся внутри этого блока. На главной отдельной копии блока нет. По умолчанию используются `https://t.me/ansanlife` и `https://t.me/ansan`. Это ссылки: тема не загружает Telegram-виджеты и ничего не отправляет в каналы.

Текст можно переопределить в проектных `i18n/ru.toml`, `i18n/en.toml`, `i18n/ko.toml` через ключ `community_story`. Формулировка «десятый год» фиксирована и в будущем потребует обновления. Блок и ссылки скрываются через `showAnsanCommunity = false`.

## Параметры

Добавляйте нужные параметры в **существующую** секцию `[params]`, не дублируя её:

```toml
[params]
  logo = "images/logo.webp"
  homePageSize = 12
  archivePageSize = 12
  mainSections = ["posts"]
  showPinStrip = true
  pinCategory = "Pin"
  pinLimit = 6
  hiddenCategories = ["Pin"]
  showArticleLead = false
  showArticleToc = false
  autoLoadNext = true
  showAnsanCommunity = true
  telegramGroup = "https://t.me/ansanlife"
  telegramChannel = "https://t.me/ansan"
```

`homeHeading`, `homeEyebrow`, `pinTitleLength` из прошлой версии больше не используются. Настройку логотипа и языков сохраняйте из своего проекта. Минимальные примеры контента и конфигурации находятся в `exampleSite/`.

## JavaScript и PageSpeed

Код темы — нативный ES module без jQuery, стороннего UI-фреймворка, транспиляции в ES5 и полифиллов. Предупреждение на вашем скриншоте об устаревшем JavaScript относится к `static.cloudflareinsights.com/beacon.min.js` — это внешний скрипт Cloudflare, а не файл темы. Изменение темы не изменяет содержимое этого внешнего файла. Настройки аналитики Cloudflare не менялись.

Для главной картинки статьи приоритет исправлен в HTML сборки. Числовой балл PageSpeed на вашем рабочем сайте здесь не измерялся; он также зависит от изображений, сервера и сторонних сервисов.

Поиск Google CSE сохранён. Нужны `content/search.<язык>.md` с `layout: search` и ваш `params.search.googleCSEID`. Сохранены SEO-метаданные, RSS, robots.txt и shortcode `vk`, `youtube`, `toc`.

## Файлы

- `layouts/home.html`, `partials/category-navigation.html` — главная и круглая навигация.
- `layouts/partials/archive.html`, `post-card.html` — архивы и карточки.
- `layouts/single.html`, `partials/article-content.html` — статья.
- `layouts/partials/related.html`, `recommendations/` — подбор похожих материалов.
- `layouts/partials/next-article.html`, `next-story.html` — переход по датам.
- `layouts/partials/community.html`, `discussion.html` — Telegram/VK.
- `assets/js/main.js` — поведение интерфейса и подгрузка.
- `assets/css/` — стили, разбитые по назначению.
- `preview/` — реальные скриншоты тестового сайта; тексты и иллюстрации демонстрационные.
- `VALIDATION.md` — результаты и границы проверки.
